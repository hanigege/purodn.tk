sing-box tcp-brutal 服务端完整教程：安装、配置与安全防护（US-232 / US-146 实战）

从零搭建 sing-box tcp-brutal 服务端：官方源安装、tcp-brutal 内核模块、VLESS+Reality 与 Hysteria2 完整配置（两台生产机 US-232 / US-146 真实配置备份）、REALITY fallback 防白嫖、fail2ban 自动封禁。小白照着做保证能搭起来。

0. 你能得到什么

读完这篇文章，你能从零搭起两台生产级 sing-box 服务端（VLESS+Reality 用于 TCP，Hysteria2 用于 UDP/游戏），并且自带完整安全防护：

  • 安装 sing-box（官方 APT 源，Debian / Ubuntu 通用）
  • 安装 tcp-brutal 内核模块（让 TCP 也享受 Hysteria 的 Brutal 带宽控制）
  • 配置 VLESS + Reality（抗封锁、免证书）
  • 配置 Hysteria2 + salamander 混淆（UDP 专用，游戏不掉线）
  • 防护 REALITY fallback 白嫖（2026-08-06 实战教训：不用凭据也能蹭流量）
  • 防护 fail2ban 自动封禁扫描器 + iptables/nftables 封禁已知盗用段

文中的两台生产机配置原样保留，作为备份和参考。

2. 安装 sing-box（官方 APT 源）

💡 为什么用官方源：sing-box 官方 deb 仓库（deb.sagernet.org）对 Debian/Ubuntu 提供稳定版，装完自带 systemd 服务文件（sing-box.service），不用手写 Unit。

Debian / Ubuntu 通用，一条龙（复制整段执行）：

sudo mkdir -p /etc/apt/keyrings && \
sudo curl -fsSL https://sing-box.app/gpg.key -o /etc/apt/keyrings/sagernet.asc && \
sudo chmod a+r /etc/apt/keyrings/sagernet.asc && \
echo 'Types: deb
URIs: https://deb.sagernet.org/
Suites: *
Components: *
Enabled: yes
Signed-By: /etc/apt/keyrings/sagernet.asc' | sudo tee /etc/apt/sources.list.d/sagernet.sources && \
sudo apt-get update && \
sudo apt-get install -y sing-box

⚠️ 常抄错：URIs: 是 https://deb.sagernet.org/（结尾有斜杠）；key 文件名是 sagernet.asc（不是 sagernet.gpg，官方文档 2026 版用 asc）。装完确认版本：

sing-box version

期望输出：sing-box version 1.13.x（本教程实测 1.13.16 / 1.13.13）。

❌ 若报 E: The repository ... does not have a Release file → 检查 sagernet.sources 拼写，尤其 Types: deb（不带中括号）。

3. 安装 tcp-brutal 内核模块

3.1 是什么

tcp-brutal 是 Hysteria 的 Brutal 拥塞控制算法移植到 TCP 的 Linux 内核模块。sing-box 的 multiplex.brutal 开启后，会通过内核 sockopt 自动切换到 brutal 拥塞控制，让 TCP 跑满你设定的带宽（不受丢包/RTT 限制）。

3.2 安装（官方一键脚本，实测可用）

bash <(curl -fsSL https://tcp.hy2.sh/)

脚本自动完成：安装 DKMS + linux-headers → 编译内核模块 → 加载。

⚠️ 可能失败点：

  • 报 Cannot find the kernel headers → 先装：sudo apt-get install -y linux-headers-$(uname -r) build-essential dkms
  • 内核升级后模块需重新编译：脚本会自动用 DKMS 处理，无需手动。

3.3 开机自动加载

echo "brutal" | sudo tee /etc/modules-load.d/brutal.conf

3.4 ⚠️⚠️ 关键警告：不要设成系统默认拥塞控制！

tcp-brutal 官方 README 明确警告：

Do I need to configure sysctl? / Can I set TCP Brutal as the system’s default congestion control? You don’t need to, and shouldn’t. Setting it as the default congestion control would slow down all connections to 1 Mbps. Programs that do support it will actively switch to using TCP Brutal congestion control on their own.

翻译成人话：不要执行 sysctl -w net.ipv4.tcp_congestion_control=brutal！那是错误示范——brutal 必须由程序（sing-box）通过 sockopt 指定带宽参数才有效，设成全局默认会把所有 TCP 连接限速到 1Mbps。

正确姿势：保持系统默认（Debian 默认 cubic，Ubuntu 用 BBR 就 bbr），sing-box 配置里开 brutal 即可，它会在连接时自动切换。

❌ 错误：sysctl -w net.ipv4.tcp_congestion_control=brutal ✅ 正确：sysctl net.ipv4.tcp_congestion_control 保持默认；只验证模块已加载：

lsmod | grep brutal

期望：brutal 16384 0（或 1）——模块在，就行了。

4. 生成凭据（每台独立！）

⚠️ 血泪教训（2026-08-02）：两台服务器曾共用同一套 UUID + Reality key + Hy2 密码，一处泄露、两台全破。每台服务器必须生成独立凭据，绝不复用。

# VLESS UUID
cat /proc/sys/kernel/random/uuid

# Reality 密钥对（PrivateKey 留在服务器，PublicKey 给客户端）
sing-box generate reality-keypair

# Reality short_id
openssl rand -hex 8

# Hysteria2 密码（24 位随机）
head -c 24 /dev/urandom | base64 | tr -dc 'a-zA-Z0-9' | head -c 24

# Hysteria2 salamander 混淆密码（24 位随机）
head -c 24 /dev/urandom | base64 | tr -dc 'a-zA-Z0-9' | head -c 24

✅ 每次生成结果记下来：UUID / PrivateKey / PublicKey / short_id / hy2 密码 / obfs 密码。服务端用 PrivateKey，客户端和网关用 PublicKey。

8. 安全防护（2026-08-06 实战：REALITY fallback 白嫖事件）

🔥 这是本文最重要的章节。2026-08-06 实测：232 节点没用却在持续消耗流量（约 36KB/s），抓到两个微软 Azure 数据中心 IP（74.7.227.154 / .143，AS8075 Microsoft）在挂机下载，单连接已拉走 31MB。根因不是后门、不是凭据泄露——是 REALITY fallback 被当免费代理白嫖。

8.1 原理：为什么"没凭据也能蹭流量"

REALITY 协议为了抗封锁，对没有有效凭据的连接不直接拒绝，而是把它伪装转发给 handshake 伪装站：

攻击者 ──443──> sing-box（无 uuid）
                 └─> 伪装成"普通 TLS 访问" ──> handshake.server（伪装站）
                     ← 伪装站的内容原样回传 ←

攻击者不需要 uuid，不需要密码，只要 443 开放就能把 sing-box 当免费代理，让伪装站把大文件吐给他，流量全记在你头上。这就是"换凭据也挡不住"的原因——根本没用到凭据。

8.2 治本：handshake 选"无大文件"的站点

fallback 白嫖的流量大小 = 伪装站能吐多少大文件：

伪装站 白嫖效果
mirrors.kernel.org（镜像站）❌ 有内核源码包/ISO（几十~几百 MB），攻击者疯狂下载
www.apple.com（大厂官网主域）✅ 主域首页只有几十 KB 网页，无大文件可白嫖

2026-08-06 已把两台服务端 + 网关全部改为 www.apple.com。

⚠️ 换伪装站必须同步改 3 处（漏一处客户端就断）：

  1. 服务端 tls.server_name + reality.handshake.server
  2. 网关 nodes.json 对应节点的 tls.server_name
  3. 你自己的客户端 SNI

候选站要求：支持 TLS 1.3、证书有效、主域无大文件。实测可用：www.apple.com / www.microsoft.com / www.cloudflare.com。

8.4 已知盗用段永久封禁

232（Debian，iptables + netfilter-persistent）：

# 已封：微软 Azure 盗用段（74.7.227.0/24）等
sudo iptables -I INPUT 1 -s 74.7.227.154 -j DROP
sudo iptables -I INPUT 2 -s 74.7.227.143 -j DROP
sudo iptables -I INPUT 3 -s 74.7.227.0/24 -j DROP
sudo iptables -I INPUT 4 -s 74.7.244.12 -j DROP
sudo iptables -I INPUT 5 -s 74.7.175.179 -j DROP

# 持久化（重启不丢）
sudo DEBIAN_FRONTEND=noninteractive apt-get install -y iptables-persistent
sudo netfilter-persistent save
sudo systemctl enable netfilter-persistent

⚠️ 必须用 -I INPUT 1（插到最前）：Debian 默认 INPUT 链第一条是 state RELATED,ESTABLISHED ACCEPT，用 -A（追加）会排在它后面，已建立的盗用连接照样放行，DROP 形同虚设。改完 systemctl restart sing-box 踢掉已建立的 socket。

146（Ubuntu，nftables 守卫 codex-singbox-guard.service）：

/etc/nftables.d/codex-singbox-guard.nft 只放行已知端口，其余公网入站默认 drop：

#!/usr/sbin/nft -f

table inet codex_singbox_guard {
  chain input {
    type filter hook input priority -10; policy accept;

    ct state established,related accept
    iifname "lo" accept
    ip protocol icmp accept
    ip6 nexthdr ipv6-icmp accept

    tcp dport 443 accept
    udp dport 443 accept
    udp dport 2096 accept

    tcp dport 29029 accept
    udp dport { 29029, 21027 } accept

11. 经验教训

  1. REALITY fallback 是免费代理：不要用镜像站/大文件站做 handshake，用大厂官网主域。
  2. 换 handshake 必须同步改 3 处（服务端 + 网关 + 客户端），漏一处就断。
  3. tcp-brutal 不要设成系统默认拥塞控制——会限速到 1Mbps。开 multiplex brutal 即可，sing-box 自动切换。
  4. 每台服务器独立凭据，复用 = 一处破、处处破。
  5. iptables DROP 要插到链首（-I INPUT 1），否则被 ESTABLISHED 规则放行。
  6. fail2ban 读文件日志：146 原本没写文件日志（只有 journald），需在 config.json log.output 指定，否则 jail 读不到。
  7. hy2 端口跳跃在网关会超时（UDP 会话重建异常），固定端口更稳。
  8. 改生产配置前永远先备份（config.json.bak-$(date +%s)）。
