Shadowsocks-rust + Caddy + WebSocket 一键部署教程（适用于 Debian 12 / Ubuntu 22.04+）

前提条件

  • 一台新装的 Debian 12（推荐）或 Ubuntu 22.04+ 服务器，已开放 TCP 80、443 端口。
  • 已将域名（例如 ssr.purodn.de5.net）解析到该服务器 IP。
  • 建议使用 root 用户或具有 sudo 权限的账户执行以下命令。

一、 环境准备

# 更新系统并安装必要工具
apt update && apt install -y curl micro git build-essential

# （可选）如果你喜欢使用 vim，也可以替换 micro 为 vim

二、 下载并安装核心组件

有两种方式：直接在服务器上 wget 下载 或 先在本地下载后通过 SFTP 上传。 以下示例均假设文件已放在 /root 目录下。

方式一：直接在服务器上下载（wget）

# 1. Shadowsocks-rust 预编译二进制（v1.15.3）
wget https://github.com/shadowsocks/shadowsocks-rust/releases/download/v1.15.3/shadowsocks-v1.15.3.x86_64-unknown-linux-gnu.tar.xz
tar -xvf shadowsocks-v1.15.3.x86_64-unknown-linux-gnu.tar.xz -C /usr/local/bin/

# 2. v2ray-plugin（v1.3.2）
wget https://github.com/shadowsocks/v2ray-plugin/releases/download/v1.3.2/v2ray-plugin-linux-amd64-v1.3.2.tar.gz
tar -xvf v2ray-plugin-linux-amd64-v1.3.2.tar.gz
mv v2ray-plugin_linux_amd64 /usr/local/bin/v2ray-plugin
chmod +x /usr/local/bin/v2ray-plugin

# 3. Caddy（v2.7.6）--- 选择任意一种安装方式
# 方式 A：使用官方 APT 源（推荐）
apt install -y debian-keyring debian-archive-keyring apt-transport-https
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | tee /etc/apt/sources.list.d/caddy-stable.list
apt update && apt install -y caddy

# 方式 B：使用官方静态二进制包（如果不想用 APT）
# wget https://github.com/caddyserver/caddy/releases/download/v2.7.6/caddy_2.7.6_linux_amd64.tar.gz
# tar -xvf caddy_2.7.6_linux_amd64.tar.gz caddy
# mv caddy /usr/bin/
# chmod +x /usr/bin/caddy

方式二：先在本地下载后通过 SFTP 上传

  1. 在本地电脑下载以下三个文件（保存到任意目录）：
    • shadowsocks-v1.15.3.x86_64-unknown-linux-gnu.tar.xz
    • v2ray-plugin-linux-amd64-v1.3.2.tar.gz
    • caddy_2.7.6_linux_amd64.tar.gz
  2. 使用 SFTP（如 FinalShell、WinSCP）将上述文件上传到服务器的 /root 目录。
  3. 登录服务器后执行：
# 1. Shadowsocks-rust
mkdir -p /usr/local/bin/ss-rust
tar -xvf /root/shadowsocks-v1.15.3.x86_64-unknown-linux-gnu.tar.xz -C /usr/local/bin/ss-rust
cp /usr/local/bin/ss-rust/ssserver /usr/local/bin/
chmod +x /usr/local/bin/ssserver

# 2. v2ray-plugin
tar -xvf /root/v2ray-plugin-linux-amd64-v1.3.2.tar.gz
mv v2ray-plugin_linux_amd64 /usr/local/bin/v2ray-plugin
chmod +x /usr/local/bin/v2ray-plugin

# 3. Caddy（静态二进制）
tar -xvf /root/caddy_2.7.6_linux_amd64.tar.gz caddy
mv caddy /usr/bin/
chmod +x /usr/bin/caddy

提示：如果你选择了方式二的 Caddy 静态二进制安装，请继续阅读下文的系统服务配置部分，其中会提供 caddy.service 的示例。

三、 配置文件

# 创建配置目录
mkdir -p /etc/shadowsocks-rust /etc/caddy

# 1. Shadowsocks-rust 配置文件
cat > /etc/shadowsocks-rust/config.json <<EOF
{
    "server":"127.0.0.1",
    "server_port":10000,
    "password":"passwd888",
    "method":"chacha20-ietf-poly1305",
    "plugin":"/usr/local/bin/v2ray-plugin",
    "plugin_opts":"server;mode=websocket;path=/jgaga"
}
EOF

# 2. Caddyfile 配置（请将域名换成你的实际域名，例如 ssr.purodn.de5.net）
# 以下示例采用「首页伪装反代到 Bing」的方案，若想使用本地静态网页伪装，请参考下方注释。
cat > /etc/caddy/Caddyfile <<EOF
ssr.purodn.de5.net {
    # 自动申请 SSL 证书
    tls your-email@example.com

    # 路径暗号匹配（必须放在首页伪装之前）
    handle /jgaga* {
        reverse_proxy localhost:10000
    }

    # 首页伪装（反代到 Bing）
    handle {
        reverse_proxy https://www.bing.com {
            header_up Host {upstream_hostport}
        }
    }
}
EOF

# 若你想把首页伪装改为「本地静态网页」，请使用以下 Caddyfile 内容（取消上面的配置，使用下面这一块）：
# cat > /etc/caddy/Caddyfile <<'EOF'
# ssr.purodn.de5.net {
#     tls your-email@example.com
#     handle /jgaga* {
#         reverse_proxy localhost:10000
#     }
#     handle {
#         root * /var/www/html
#         file_server
#         try_files {path} /index.html
#     }
# }
# EOF
# 然后记得创建网站目录并放置测试页（见下文「验证」部分）。

四、 注册系统服务（开机自启）

# 1. Shadowsocks-rust 服务文件
cat > /etc/systemd/system/ss-rust.service <<EOF
[Unit]
Description=Shadowsocks-rust Service
After=network.target

[Service]
Type=simple
User=root
ExecStart=/usr/local/bin/ssserver -c /etc/shadowsocks-rust/config.json
Restart=on-failure

[Install]
WantedBy=multi-user.target
EOF

# 2. Caddy 服务文件
# 如果你是通过 APT 安装的 caddy，可直接使用以下内容；
# 如果你是通过静态二进体安装（放在 /usr/bin/caddy），同样适用。
cat > /etc/systemd/system/caddy.service <<EOF
[Unit]
Description=Caddy
Documentation=https://caddyserver.com/docs/
After=network.target network-online.target
Requires=network-online.target

[Service]
Type=notify
User=root
Group=root
ExecStart=/usr/bin/caddy run --environ --config /etc/caddy/Caddyfile
ExecReload=/usr/bin/caddy reload --config /etc/caddy/Caddyfile --force
TimeoutStopSec=5s
LimitNOFILE=1048576
LimitNPROC=512
PrivateTmp=true
ProtectSystem=full
AmbientCapabilities=CAP_NET_BIND_SERVICE

[Install]
WantedBy=multi-user.target
EOF

# 重新加载 systemd 配置，启用并启动服务
systemctl daemon-reload
systemctl enable --now ss-rust caddy

# 检查服务状态（应显示 active (running)）
systemctl status ss-rust caddy

五、 防火墙与内核加速（必做）

# 1. 开启 BBR 拥塞控制算法
echo "net.core.default_qdisc=fq" >> /etc/sysctl.conf
echo "net.ipv4.tcp_congestion_control=bbr" >> /etc/sysctl.conf
sysctl -p

# 2. 安装并配置简易防火墙（以 ufw 为例）
apt install -y ufw
ufw allow 22/tcp
ufw allow 80/tcp
ufw allow 443/tcp
ufw allow 443/udp
ufw allow in on lo
ufw enable

# 查看防火墙状态
ufw status verbose

六、 验证与客户端配置

1. 查看 Caddy 日志确认 TLS 申请成功

journalctl -u caddy --no-pager | tail -n 20

你应看到类似：

{"level":"info","msg":"enabling automatic TLS certificate management","domains":["ssr.purodn.de5.net"]}

2. 创建测试网页（若使用本地静态伪装方案）

mkdir -p /var/www/html
echo "<h1>Hello! This is my local decoy site.</h1>" > /var/www/html/index.html
chown -R caddy:caddy /var/www/html
chmod -R 755 /var/www/html

3. 浏览器访问验证

  • 打开浏览器访问 https://ssr.purodn.de5.net （不挂代理）：
    • 若看到 Bing 首页（或你放置的测试网页），说明 Caddy 和 TLS 证书正常。
  • 访问 https://ssr.purodn.de5.net/jgaga 应该会被反代到本地 10000 端口的 Shadowsocks-rust 服务（此时你的客户端应能连通）。
  • 若出现 403，请检查 /var/www/html 目录的权限是否为 caddy:caddy 且目录可读。
  • 若出现 404，请确认 Caddyfile 中 root 路径和 try_files 配置正确。

4. 客户端参数对照表（以常见 Shadowsocks 客户端为例）

选项 设置值 说明
服务器 ssr.purodn.de5.net 你的域名
端口 443 必须是 HTTPS 端口
密码 passwd888 与服务器端保持一致
加密方式 chacha20-ietf-poly1305 性能之选
插件 v2ray 或对应的 v2ray-plugin
插件选项 mode=websocket-tls;host=ssr.purodn.de5.net;path=/jgaga 暗号（path）必须与服务器端 /jgaga 对齐

注意：部分客户端插件选项写法略有差异，例如 websocket;host=ssr.purodn.de5.net;path=/jgaga;tls，请根据客户端文档调整，但核心是 path=/jgaga 和开启 TLS。

七、 常见问题快速排查

  1. 检查服务器端口通不通（在本地机器终端执行）

    nc -vz ssr.purodn.de5.net 443
    • 返回 succeeded：说明 IP 和端口没死，问题可能在配置或 DNS。
    • 长时间卡住显示 Timeout：IP 或端口大概率被墙。

  2. 检查域名解析是否正常

    ping ssr.purodn.de5.net
    • 返回的 IP 应该是你服务器的真实 IP。若出现 0.0.0.0 或奇怪的国外 IP，说明域名被 DNS 投毒。

  3. 检查 Caddy 是否还在工作

    在浏览器直接访问 https://ssr.purodn.de5.net（不挂代理）：

    • 能看到伪装页面 → Caddy 和 TLS 证书正常。
    • 连伪装页都打不开 → 443 端口可能已断。

以上步骤完成后，你即可在客户端使用上表参数连接，享受由 Shadowsocks-rust + Caddy + WebSocket 提供的高性能、可观流量的代理服务。祝使用愉快！

八、 进阶：Docker Compose 一键部署方案

如果你希望在多台机器上快速复制、避免手动编写 systemd 服务文件，或者想实现一键升级/回滚，可以使用 Docker Compose 将 Shadowsocks-rust、v2ray-plugin 和 Caddy 打包成容器运行。

为什么 Docker 方案更好？

  • 一键启动：一条 docker compose up -d 完成所有服务部署
  • 跨平台：x86、ARM、云主机通用，无需关心底层系统差异
  • 快速升级：修改镜像标签后 docker compose pull && docker compose up -d 即可完成升级
  • 配置隔离：所有配置通过卷挂载，修改配置无需重新构建镜像
  • 自动重启：restart: unless-stopped 策略替代 systemd 服务文件
  • 易于备份/迁移：整个目录打包即可迁移到另一台机器

前置要求

  • 已安装 Docker 和 Docker Compose Plugin 
    # Debian/Ubuntu 一键安装 Docker
curl -fsSL https://get.docker.com | bash

# 验证安装
docker --version
docker compose version

目录结构

~/ss-caddy-docker/
├── docker-compose.yml      # 主配置文件
├── Caddyfile               # Caddy 配置
├── config.json             # Shadowsocks-rust 配置
└── www/                    # （可选）本地静态伪装网页目录
    └── index.html

1. 创建目录并编写配置文件

mkdir -p ~/ss-caddy-docker/www
cd ~/ss-caddy-docker

docker-compose.yml

version: "3.8"

services:
  shadowsocks-rust:
    image: ghcr.io/shadowsocks/shadowsocks-rust:v1.15.3
    container_name: ss-rust
    restart: unless-stopped
    volumes:
      - ./config.json:/etc/shadowsocks-rust/config.json:ro
    network_mode: "host"
    command: ["ssserver", "-c", "/etc/shadowsocks-rust/config.json"]

  caddy:
    image: caddy:2.7.6
    container_name: caddy
    restart: unless-stopped
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
      - ./www:/var/www/html:ro
    network_mode: "host"
    environment:
      - ACME_AGREE=true
    cap_add:
      - NET_BIND_SERVICE

volumes:
  caddy_data:
  caddy_config:

config.json（与二进制方案相同）

{
    "server":"127.0.0.1",
    "server_port":10000,
    "password":"passwd888",
    "method":"chacha20-ietf-poly1305",
    "plugin":"/usr/local/bin/v2ray-plugin",
    "plugin_opts":"server;mode=websocket;path=/jgaga"
}

注意：官方 shadowsocks-rust 镜像已内置 v2ray-plugin，无需额外容器。

Caddyfile（与二进制方案相同）

ssr.purodn.de5.net {
    tls your-email@example.com

    handle /jgaga* {
        reverse_proxy localhost:10000
    }

    handle {
        root * /var/www/html
        file_server
        try_files {path} /index.html
    }
}

测试网页（可选）

echo "<h1>Hello! This is my Docker decoy site.</h1>" > www/index.html

2. 启动服务

cd ~/ss-caddy-docker

# 启动所有容器
docker compose up -d

# 查看运行状态
docker compose ps

# 查看 Caddy 日志（确认 TLS 证书申请成功）
docker compose logs -f caddy

3. 防火墙放行

# 如果使用 ufw
ufw allow 80/tcp
ufw allow 443/tcp
ufw allow 443/udp
ufw reload

4. 验证

与二进制方案的验证步骤相同：

# 查看 Caddy 日志确认 TLS 申请成功
docker compose logs caddy | grep "enabling automatic TLS"

# 浏览器访问 https://ssr.purodn.de5.net 查看伪装页面
# 访问 https://ssr.purodn.de5.net/jgaga 测试代理连通性

5. 日常维护命令

# 查看日志
docker compose logs -f          # 所有服务
docker compose logs -f caddy    # 只看 Caddy
docker compose logs -f ss-rust  # 只看 Shadowsocks

# 重启服务
docker compose restart

# 停止服务
docker compose down

# 更新镜像（升级版本）
docker compose pull
docker compose up -d

# 查看资源占用
docker stats

6. 迁移到新机器

# 在原机器上打包
cd ~
tar -czvf ss-caddy-docker.tar.gz ss-caddy-docker/

# 传输到新机器（scp/sftp/rsync）
scp ss-caddy-docker.tar.gz user@new-server:~/

# 在新机器上解压并启动
ssh user@new-server
tar -xzvf ss-caddy-docker.tar.gz
cd ss-caddy-docker
docker compose up -d

注意事项

  1. network_mode: “host” 让容器直接使用宿主机网络，Caddy 可以直接绑定 80/443 端口，这是最简单的方案。如果你需要使用 Docker 的桥接网络，需要额外配置端口映射，并注意 Caddy 的 ACME 验证需要能访问到宿主机的 80/443。

  2. 镜像版本锁定：建议将 latest 替换为具体版本号（如 v1.15.3、2.7.6），避免自动拉取不兼容的新版本。

  3. v2ray-plugin：官方 shadowsocks-rust 镜像已内置 v2ray-plugin，无需单独容器。如果你需要自定义插件版本，可以挂载自己的二进制文件覆盖。

  4. 资源限制：如需限制容器资源，可在 docker-compose.yml 中添加：

    deploy:
  resources:
    limits:
      cpus: '0.5'
      memory: 512M

教程中出现的域名、密码、路径均为示例，请根据你的实际情况替换。
