Hermes Agent 文件约定：SOUL.md vs .hermes.md vs AGENTS.md

一、一句话结论（先看这个）

  1. 想让所有项目都生效的规则，只能写进 SOUL.md；~/.hermes/ 根目录下放 .hermes.md / AGENTS.md / HERMES.md 完全无效。
  2. .hermes.md 必须放在项目根目录才能作为全项目的“最高法”穿透所有子目录；放在子目录则无法作用于其他同级或上级目录。
  3. .hermes.md 与 HERMES.md 同时存在时不会叠加应用，系统仅优先加载 .hermes.md。

二、源码级加载规则（按优先级）

Hermes 每次构造 system prompt 时，会调用 build_context_files_prompt()，规则如下：

优先级文件查找位置用途
1.hermes.md 或 HERMES.md从 当前工作目录（CWD） 向上走到 git 仓库根项目宪法（最高优先级）
2AGENTS.md仅 CWD，不递归项目开发规范
3CLAUDE.md仅 CWDClaude Code 兼容
4.cursorrules、.cursor/rules/*.mdc仅 CWDCursor 兼容
—SOUL.md始终从 HERMES_HOME（profile 根目录）人格 + 全局行为准则

关键事实：

  1. 上面 1-4 是优先级，找到第一个就停。
  2. SOUL.md 独立加载，与项目文件并存，不是替代关系。
  3. .hermes.md 和 HERMES.md 等价，但互斥不叠加——源码按 (".hermes.md", "HERMES.md") 顺序查找，匹配到第一个即停止。若根目录同时存在两者，HERMES.md 将被直接忽略。
  4. AGENTS.md 不递归。v0.5 之后明确改成"top-level only"，旧文章里说的"递归发现子目录 AGENTS.md"已经过时。
  5. ~/.hermes/ 不是工作目录，把 .hermes.md 或 HERMES.md 放在这里永远不会被加载。

三、常见误解纠正

❌ 误解 1：把 .hermes.md 放 ~/.hermes/ 当全局配置

真相：.hermes.md 是项目级文件，查找起点是 CWD。~/.hermes/ 是 Hermes 自己的状态目录，agent 工作时 CWD 通常是用户的项目目录，根本走不到 ~/.hermes/。想让规则全局生效，唯一正确的位置是 SOUL.md。

❌ 误解 2：.hermes.md 放在项目任意子目录都能作为“全项目最高法”

真相：.hermes.md 的查找机制是从当前工作目录（CWD）向上一路找至 Git 根目录。如果把它放在 backend/ 子目录，当你进入 frontend/ 或项目根目录工作时，系统完全感知不到它的存在。只有将其存放在项目根目录，才能穿透全项目所有子目录。

❌ 误解 3：同时创建 .hermes.md 和 HERMES.md 可以双重生效或补充

真相：系统加载时“找到即停”。同时存在时，系统仅读取 .hermes.md，HERMES.md 会被完全忽略。建议项目内统一只保留一个隐藏文件 .hermes.md。

❌ 误解 4：AGENTS.md 会递归发现子目录

真相：v0.5 起改为 top-level only。如果你以前在 backend/AGENTS.md、frontend/AGENTS.md 各放一份期望都被加载，只有 CWD 所在那一份生效。官方理由：递归加载会浪费大量 token，且子目录规则经常和顶层冲突。

❌ 误解 5：SOUL.md 只能写“人格”

真相：SOUL.md 是 profile 级唯一全局生效的指令文件。除了人格/语气，行为准则（比如“用简体中文”、“用金字塔原理”）也必须写在这里——它是你跨所有项目、跨所有 CWD 都生效的唯一通道。

四、实战：蜜和佬的配置

背景

  • 蜜：default profile，跑日常助手任务，HERMES_HOME = ~/.hermes/
  • 佬：code profile，跑代码任务，HERMES_HOME = ~/.hermes/profiles/code/
  • 两个 bot 共享同一台机器的同一个用户，CWD 经常是 ~/codex/hugo/、~/data/docker_data/ 等项目目录。

需求 1：让蜜和佬都用简体中文 + 金字塔原理

错误做法 ❌：写 ~/.hermes/.hermes.md（不会被加载）。 正确做法 ✅：写进各自 profile 的 SOUL.md。

蜜的 ~/.hermes/SOUL.md：

# 行为准则

- 以简体中文输出
- 使用第一性原理思考
- 用金字塔原理组织输出

佬的 ~/.hermes/profiles/code/SOUL.md：（同样内容，独立维护） 这样无论蜜/佬当前 CWD 是哪里，准则都生效。

需求 2：给 sing-box 项目（~/codex/sb-alpine/）定规则

这是 Alpine Linux 的 sing-box 面板项目，要求“只支持 Alpine + OpenRC”、“修改前必读 AGENTS.md”。

正确做法 ✅：在项目根目录 ~/codex/sb-alpine/ 下放置文件。

~/codex/sb-alpine/.hermes.md（项目宪法，必须放在根目录）：

# 行为准则

- 仅支持 Alpine + OpenRC
- 修改前必读 AGENTS.md

~/codex/sb-alpine/AGENTS.md（根目录开发规范）：

# AGENTS.md

## sing-box 开发规范

- 使用 musl 工具链
- 禁用 systemd
- 配置文件放置 /etc/sing-box/

效果：无论蜜还是佬，只要 CWD 进入 ~/codex/sb-alpine/（或它的子目录），.hermes.md 会沿目录树向上找到并加载；AGENTS.md 仅在 CWD 正好是项目根时加载。

需求 3：在 ~/codex/sb-alpine/backend/ 子目录干活

情况：CWD 是 ~/codex/sb-alpine/backend/ 加载结果：

  • .hermes.md：从 ~/codex/sb-alpine/backend/ 向上走，在根目录 ~/codex/sb-alpine/ 找到 ✅ 加载
  • AGENTS.md：仅查当前 ~/codex/sb-alpine/backend/，根目录的不加载 ❌（除非 backend/ 下有独立的 AGENTS.md）
  • SOUL.md：始终从 HERMES_HOME 加载 ✅

结论：项目全局不可违反的“红线”必须写在项目根目录的 .hermes.md；而特定模块的开发指南写在对应目录下的 AGENTS.md。

五、决策表（什么时候用哪个）

你的需求该写的文件位置
让某个 bot 全局遵守某些规则（语言/思考方式/风格）SOUL.mdprofile 根目录
项目不可违反的红线（技术栈/禁忌）.hermes.md项目根目录（确保全项目生效）
针对某具体目录的开发流程/规范AGENTS.md对应的当前工作目录（不递归）
给 Claude Code 兼容用CLAUDE.md项目根目录（但 .hermes.md 优先）
给 Cursor 兼容用.cursorrules项目根目录（优先级最低）

一句话记忆法： SOUL→全局人格，.hermes.md→项目根目录红线，AGENTS.md→局部目录流程。

六、验证方法（防止再被旧文章误导）

下次再看到“Hermes 加载 XX 文件”的说法，直接查源码：

  • build_context_files_prompt_project() — 定义 .hermes.md / HERMES.md 查找逻辑（CWD → git root）
  • build_context_files_prompt_cwd() — 定义 AGENTS.md / CLAUDE.md / .cursorrules 查找逻辑（仅 CWD）
  • build_context_files_prompt() — 总入口，注释里明确优先级
